# Claude API Switcher V4.5 可靠性与舒适度升级设计

## 目标

在不改变五个一级入口、不迁移用户密钥、不破坏 V4.4 配置的前提下，修复会造成错误路由、长时间卡顿、状态显示不真实和高 DPI 操作困难的问题。V4.5 先生成本地候选版，完成源码与 EXE 验收后再由用户决定是否发布。

## 方案选择

- 方案 A：只修崩溃和超时。风险最低，但用户可感知提升有限。
- 方案 B：可靠性底座加关键界面修整。覆盖真实故障和主要体验问题，仍保持现有架构。采用此方案。
- 方案 C：拆分 13 万字节的 `gui.py` 并重做信息架构。长期价值高，但当前回归风险和工期不合适。

## 可靠性设计

1. Claude 子进程环境除清理 `ANTHROPIC_*` 外，也清理 Bedrock、Vertex、Foundry 路由开关，确保界面选择的供应商是唯一会话路由。
2. gcli2api 额度查询采用受限并发、短单项超时和整体时间预算。个别凭证失败时保留其他凭证的结果，并在快照消息中标明部分失败。
3. Gemini 自动切换在一次锁内读取地址、密码、模型、额度和首选模型，单次请求不混用不同配置代际。
4. 配置载入校验 JSON 根结构和 Provider 列表。损坏配置先备份再创建默认配置；旧 Provider ID 规范化后立即原子持久化。
5. Provider 导出包含优先级，导入校验并恢复优先级，保证无密钥配置往返一致。
6. 软件更新链接只接受本项目的 HTTPS GitHub Release 地址，拒绝 API 响应中的任意外站 URL。

## 界面设计

1. 用量页“路由策略”开关显示真实配置，写入失败时恢复原值并给出原因。
2. 暗色次要文字提高对比度；正文和图表辅助字号不低于 11–13px，热力图仍保留数值提示与文字图例。
3. 帮助提示框使用主题语义色，处理屏幕上下左右边界，扩大点击区域，并支持失焦和 Escape 关闭。
4. Provider 与网关 Provider 对话框按屏幕工作区限制尺寸，允许调整窗口；所有编辑窗口都使用真正模态行为，防止重复编辑。
5. 不在本轮移动页面或删除现有功能，降低已有用户的学习和回归成本。

## 错误处理

- 网络/额度操作必须有明确的单项超时、总时限和部分成功语义。
- 配置恢复必须保留一份带时间戳的损坏文件，不静默覆盖唯一副本。
- UI 开关保存失败必须回滚显示值；后台线程不得把旧操作结果覆盖到新状态。
- 错误信息不包含 API Key、密码、OAuth JSON 内容或 Authorization 头。

## 验收

- 新增单元测试覆盖路由变量清理、自动切换配置一致性、额度总时限/部分成功、配置结构恢复、旧 ID 持久化、优先级往返、更新 URL 限制和路由开关回滚。
- 完整测试、`compileall`、当前目录 `pyinstaller --clean` 全部通过。
- 源码版与成品 EXE 分别在浅色和深色下检查 API、Gemini、用量、设置页面，验证正常退出且 7861/8787 无残留监听。

## 本轮不做

- 代码签名需要有效的签名证书，不能在本轮凭空完成。
- 网关 SQLite 密钥迁移到 Windows Credential Manager 涉及兼容与回滚设计，单独作为后续安全版本处理。
- 不重写 V3 未接入主界面的实验模块，不宣称其为 EXE 已发布能力。
