# gcli2api 导入后测试误报超时修复设计

## 问题与证据

供应商测试器对所有 API 使用固定 15 秒超时。Antigravity 导入凭证后，gcli2api 可能先刷新 Google 凭证，再对首选模型发起请求；若首选模型返回 429，本软件网关还会在输出前切换到下一个模型。该流程实测约 25 秒，但测试器会在第 15 秒主动断开并显示“超时”。日志在 05:21 和 05:23 两次均精确复现，且当时 7861、8787 均处于监听状态。

## 选定方案

保持普通供应商 15 秒超时，仅为 `provider_kind=gcli2api` 使用 90 秒测试超时。真实业务网关的上游超时仍保持 120 秒，不因测试场景降低正常长回答的可用性。

不采用全局延长，因为会降低其他供应商错误反馈速度；不采用只测健康接口，因为健康状态无法验证 JSON 凭证、模型额度与真实消息调用。

## 行为

- `ApiTester` 根据供应商类型选择请求超时：普通供应商 15 秒，gcli2api 90 秒。
- gcli2api 测试进行时，供应商卡片提示正在验证凭证并尝试可用模型，用户知道自动切换可能需要更久。
- 只有请求达到 gcli2api 专用超时时间后才显示“超时”；429 继续显示模型额度耗尽、恢复时间与切换建议。
- 返回成功时仍显示实际总耗时；认证失败、连接失败、重定向和其他 HTTP 错误保持原分类。
- 不记录或显示 API 密码、JSON 凭证或 Google token。

## 验收

- 单元测试证明普通供应商仍传入 15 秒，gcli2api 传入 90 秒。
- 单元测试证明 gcli2api 超时消息包含 90 秒而非 15 秒。
- 完整测试套件通过。
- 使用当前已导入凭证和本地 8787 网关执行最小消息测试，确认不再在 15 秒提前失败。
- 重新构建并替换桌面 V4.3.0 EXE，本轮不推送 GitHub。
