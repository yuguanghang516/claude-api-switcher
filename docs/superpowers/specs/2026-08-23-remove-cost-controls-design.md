# 移除成本控制设计

日期：2026-08-23

## 问题

“用量监控”中的“成本控制”使用静态价格表估算花费，并在预算超限后自动切换低价模型。它与当前强调真实 Token、真实网关调用和官方余额口径的监控设计不一致，也会让用户误以为软件掌握供应商真实账单和剩余额度。

## 目标

- 从“用量监控”页面完整移除“成本控制”卡片、预算进度和按模型估算花费。
- 从本地网关移除预算判断、预算超限自动切换、预算通知和 `/v2/cost` 接口。
- 删除不再使用的 `CostController` 模块及对应测试。
- 保留真实的 Claude 本机 Token、7 天热力图、各 API 网关调用统计、供应商官方余额和路由/故障转移功能。
- 不把估算成本改名后继续保留，也不使用静态价格伪装真实账单。
- 不主动删除用户现有 `v2_config.json` 中的历史 `budget` 字段；升级后忽略该字段，避免对用户文件执行破坏性迁移。

## 范围

界面不再构建或刷新成本控制区域。网关不再创建成本控制器，不再在请求前检查预算，也不再在响应后累计估算费用。网关能力列表移除 `cost_control`，旧 `/v2/cost` 路由停止提供。

静态价格查询模块暂时保留为独立的开发接口，因为用户本次要求移除的是会影响请求路由和界面判断的“成本控制”；它不能再驱动预算、自动切换或余额显示。若后续确认没有任何调用方，再单独删除价格参考模块。

通知系统中的预算专用通知入口随成本控制一起删除；普通 API 错误、故障转移和系统通知保持不变。

## 验证

- 自动化测试确认用量监控不再创建成本控制控件。
- 自动化测试确认网关请求不会因预算状态切换模型。
- 全局搜索确认运行时代码不存在 `CostController`、`cost_control`、`/v2/cost` 或预算回调引用。
- 完整运行 pytest 测试集。
- 构建 EXE，确认用量监控页面布局连续，真实 Token、热力图、网关用量和余额卡片仍正常显示。
- 确认用户数据文件没有被主动删除，GitHub 远端没有更新。
