# 版本与支持卡片设计

日期：2026-08-23

## 目标

在“环境设置”页面底部增加与现有深色/浅色主题一致的“版本与支持”卡片。卡片参考用户提供图片的信息层级，但使用本项目自己的视觉规范和真实链接。

卡片提供：当前版本、检查更新、GitHub 项目、反馈问题、版本发布和更新日志。所有按钮使用明确文字，最小高度 34 像素，并在后台执行网络检查，避免界面卡顿。

## 链接

- 项目：`https://github.com/yuguanghang516/claude-api-switcher`
- 反馈问题：`https://github.com/yuguanghang516/claude-api-switcher/issues/new`
- 版本发布：`https://github.com/yuguanghang516/claude-api-switcher/releases`
- 更新日志：优先打开最新 Release；没有公开 Release 时打开仓库内 `docs/releases`。

## 检查更新

软件仅在用户点击“检查更新”后请求 GitHub Releases API，不在后台自动联网。检查器读取最新公开 Release 的标签、标题、发布日期和下载页，并与 `app/version.py` 中的当前版本做语义版本比较。

- 已是最新版：显示当前版本和最新公开版本相同。
- 发现新版：显示版本号和发布日期，并提供“打开下载页”；不自动下载或运行 EXE。
- 仓库尚无公开 Release：明确显示“尚未发布公开版本”，不把 GitHub 404 误报为网络故障。
- 网络失败：区分超时、DNS/断网、代理或 GitHub 访问受限。
- 返回格式异常：显示“GitHub 返回了无法识别的版本信息”。

检查过程显示加载状态并临时禁用按钮；无论成功失败都恢复按钮。日志和错误提示不得包含代理凭据、Token 或完整响应正文。

## 验证

- 测试语义版本比较，包括 `v4.2.0`、预发布版本、相同版本和无效标签。
- 测试最新版、新版、无 Release、超时、连接失败和异常 JSON。
- 测试所有按钮使用正确仓库地址。
- 深色和浅色主题下检查卡片的对比度、文字截断和按钮布局。
- EXE 中实际点击链接并确认由默认浏览器打开；不自动下载文件。
