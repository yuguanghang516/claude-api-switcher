# 真实用量与余额监控设计

日期：2026-08-23

## 目标

在“额度监控”中区分三类数据，禁止把密钥可用性、速率限制或本地估算冒充账户余额：

1. Claude 本机用量：只读取 Claude Code 本地会话文件中的时间、模型和 `usage` Token 字段，不读取、保存或展示聊天内容。
2. 软件网关用量：根据本地请求日志，按供应商统计调用次数、成功/失败次数以及输入、输出和总 Token。
3. 供应商官方余额：仅在供应商有公开、稳定接口时显示“官方余额”；没有接口时显示“不支持自动查询”及原因，并提供官方用量页面入口。

## 数据边界

### Claude 本机用量

扫描 `%USERPROFILE%\.claude\projects` 下的 JSONL 会话文件，只消费 assistant 消息的模型、时间、消息 ID 和 usage 数字。相同消息 ID 只保留一条，避免流式或重复记录造成重复计数。损坏、超大或无权限文件跳过并计入诊断，不阻塞界面。

本机记录通常没有 API Key 或供应商账号标识，因此按模型统计；能够通过唯一模型名匹配当前供应商时可显示供应商名称，否则标记为“按模型统计，供应商未知”。

### 网关用量

修正网关请求日志的供应商字段，在新请求中记录实际路由到的供应商。旧记录没有供应商时显示“历史记录未标注”，不能猜测。统计今日、本月和累计调用次数及 Token。

### 官方余额

官方接口适配器使用固定允许列表，不把自定义 Base URL 拼接成余额地址，不跟随跨主机重定向，也不记录密钥。DeepSeek 使用其公开余额接口。Anthropic、Google/gcli2api 和当前 LongCat 公共文档未提供可用的账户余额接口，因此分别标记为“不支持自动查询”，并给出官方控制台或面板入口。

LongCat 显示本机已统计的 LongCat Token；“账户剩余”显示“需在 LongCat Usage 页面查看”，并提供按钮。不能使用调用成功、HTTP 200 或模型列表来显示虚假的 100%。

## 界面

额度监控页从上到下展示：

- 数据口径说明，明确“本机统计不等于供应商账单”。
- Claude Code 本机用量卡：今日/本月调用、输入/输出/缓存 Token，按模型明细。
- API 调用用量卡：按供应商展示本地网关统计。
- 官方账户余额卡：数据来源、刷新时间、余额或不支持原因，并提供外部页面入口。

所有刷新在后台线程执行，按钮显示忙碌状态；失败时保留其他可用数据，并把原因写在对应卡片，不弹出包含密钥的异常文本。

## 验证

- 用临时 JSONL 验证隐私字段忽略、消息去重、日期汇总、损坏文件容错和大小限制。
- 验证网关按供应商聚合，旧数据不误归属。
- 验证余额类型区分真实余额、仅可用性、不支持和错误；不再产生虚假 100%。
- 完整 pytest 回归、PyInstaller 单文件构建、浅色/深色界面检查和 EXE 启动关闭验证。
- 仅本地提交和交付，不推送 GitHub。
