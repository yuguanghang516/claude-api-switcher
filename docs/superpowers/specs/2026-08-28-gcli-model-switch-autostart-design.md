# Gemini 反代模型切换与自动启动设计

## 目标

把 Gemini 反代从“先去反代页启动服务，再回 API 页测试”的两段流程，改成第一页一次点击即可完成；同时把 gcli2api 返回的技术性模型别名从用户选择列表中移除，并在额度列表直接提供明确的模型切换入口。

## 模型列表

- gcli2api 的 `假流式/<模型>` 与 `流式抗截断/<模型>` 是同一基础模型的传输变体，不作为独立模型展示。
- Claude-facing 模型列表只保留正常文本模型名，并按原顺序去重。
- 内部图片、Agent、Tab、Chat 等非 Claude 文本模型继续过滤。
- 已保存的旧别名在读取时归一化为基础模型，避免升级后继续显示脏名称。

## 额度页切换

- 在每条可见模型额度的右侧增加“切换使用”按钮。
- 当前首选模型显示“当前使用”，按钮禁用，形成明确状态。
- 点击其他模型后立即：
  1. 更新 Gemini 反代页的首选模型；
  2. 重新配置 8787 自动切换网关的 preferred model；
  3. 更新第一页已保存的 gcli2api 供应商主模型与快速模型；
  4. 保存配置，使软件下次启动继续使用该模型；
  5. 刷新额度列表和第一页供应商卡片。
- 切换动作不伪造“模型可用”。额度为 0 的模型仍允许用户主动选择，但按钮和提示明确标注“快照耗尽”；真实调用仍以 429 为准并触发自动切换。

## 第一页自动启动

- 当用户对 gcli2api 供应商点击“测试”或“测试并使用”时，测试线程先执行准备流程：
  1. 从已保存供应商读取本地 API 密码、模式和模型；
  2. 检测 7861 gcli2api 服务；
  3. 服务未运行时，使用保存的密码自动启动 gcli2api，并等待服务就绪；
  4. Antigravity 模式下刷新可用模型/额度并配置自动切换；
  5. 若供应商地址为 8787，自动启动本地 Anthropic 网关；
  6. 最后执行原有 API 测试，成功后再设为当前供应商。
- 服务已由终端或其他进程启动时只复用，不重复拉起或终止外部进程。
- 远程 gcli2api 地址不尝试本地启动，只进行连接测试。

## 状态与错误提示

- 准备阶段显示“正在启动 Gemini 服务并准备模型…”，测试阶段显示“正在验证凭证并尝试可用模型…”。
- 未安装：提示前往 Gemini 反代页执行一键安装。
- 缺少密码：提示在 Gemini 反代页填写或生成本地 API 密码。
- 启动失败：显示 gcli2api 返回的具体原因，不继续测试。
- OAuth/凭证未完成：服务可以启动，但提示打开面板完成 Antigravity 登录。
- 8787 端口冲突：明确提示本地网关端口被占用，不把它误报为 API 超时。

## 代码边界

- `Gcli2ApiManager` 负责模型名归一化、服务检测和启动。
- `MainWindow` 负责 UI 状态、额度行切换、保存供应商模型，以及按顺序编排启动与测试。
- `GatewayServer` 继续只负责 8787 转发与 429 模型切换，不承担 UI 或持久化职责。
- `ProviderManager` 继续负责安全读取凭据、测试和设置当前供应商。

- 单元测试覆盖服务已运行、服务停止后自动启动、未安装、缺少密码、启动失败、8787 启动失败。
