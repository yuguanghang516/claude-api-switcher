# Claude API Switcher V4.4 发布前体验与稳定性设计

## 背景

V4.3.2 已修复用户级 `~/.claude/settings.json` 导致的 LongCat 串线，但发布前实机审计仍发现四类问题：项目目录内的 Claude 设置仍可能覆盖当前供应商；Gemini 多模型切换最坏等待过长；API 首页没有优先展示当前供应商；用量页字体、对比度和数据来源说明不足，历史模型记录容易被误认成当前路由。

## 目标

1. 软件启动 Claude 时，当前供应商必须优先于用户级和项目级旧路由。
2. Gemini 自动切换保留多模型容错，但一次请求的总等待受控并有明确结果。
3. API 首页第一眼就能看到当前供应商，未配置项不会抢占视觉注意力。
4. 用量页明确区分历史 Claude 模型用量、API 调用统计和供应商余额/额度。
5. 保持现有配置、凭据和数据库兼容，不修改全局 Claude 设置。

## 方案

### Claude 设置源隔离

启动器读取所选项目的 `.claude/settings.json` 与 `.claude/settings.local.json`，只检查 `env` 中是否存在 `ANTHROPIC_` 路由键，不记录或输出值。优先选择无路由污染的 `local` 设置源；若 local 有冲突而 project 无冲突，则使用 `project`。若两者都有冲突，停止启动并明确告诉用户需要移除项目级旧 API 路由，绝不静默启动到错误供应商。用户级设置源始终排除。

### Gemini 自动切换预算

`GcliModelFailover` 增加单次尝试和整次转发的时间预算。候选模型仍按当前模型、同家族、额度和能力排序；429、超时或连接失败时尝试下一个模型。剩余预算不足时返回最后一个可解释响应或超时，不再让三次 120 秒等待串联。流式请求只在尚未向客户端输出字节前切换。

### API 首页供应商排序

供应商列表按“当前使用 → 已配置且启用 → 已配置但停用 → 未配置”排序。当前供应商卡增加清楚的“当前使用”状态，未配置卡降低视觉权重。测试、选择和快速启动仍沿用现有安全流程。

### 用量页信息层级

- 页面主标题、段落、指标卡和列表统一使用微软雅黑语义字号。
- 热力图增加从“低”到“高”的图例，并提高暗色主题下空单元格、标签和边框对比度。
- 模型区命名为“历史 Claude 模型用量”，说明模型名称来自 Claude 本机历史记录，不表示当前供应商。
- API 区命名为“本地网关 API 调用”，说明只统计本软件 8787 网关。
- Gemini gcli2api 余额项不再显示笼统的“不可用”，改为引导到 Gemini 反代页查看实时模型额度。

## 错误处理

- 项目设置文件无法解析时，视为不安全并返回包含文件名和处理方法的错误，不读取或显示凭据值。
- Gemini 超时信息区分单模型超时和整体预算耗尽。
- 所有异步刷新继续在后台线程执行；按钮必须有执行中、成功或失败状态。

## 测试与验收

- 单元测试覆盖 local/project 设置源选择、双冲突拒绝和畸形 JSON。
- 单元测试覆盖 429 切换、超时切换和总预算上限。
- 单元测试覆盖当前供应商排序和 Gemini 额度引导文案。
- 完整自动化测试、源码 GUI 冒烟测试、单文件 EXE 构建和正常关闭测试均通过。
- 本轮只生成本地候选版，不推送、不打标签、不创建 GitHub Release。
