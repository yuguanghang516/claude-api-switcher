# V4.6.2 本地候选版

## 本轮修复

- API 切换页支持填入服务根地址、`/v1` 地址或完整 `/v1/messages` 地址，统一规范化；测试和新启动的 Claude 会话使用一致的路由，避免 `/v1/v1/messages`。
- 连通性测试检查 Anthropic 消息响应。HTTP 200 登录页、健康页、OpenAI 格式和错误 JSON 不再误报“正常”。提示用户确认 API 地址及协议。
- 无效 IPv6、非数字或越界端口不会再抛出未处理异常；拒绝在 API 地址中携带账号密码、查询参数或片段，避免错误路由与密钥泄露。
- 默认禁用的未配置供应商、空供应商列表可正常导出和重新导入。
- 导入严格校验启用状态，字符串 `"false"` 不再被误转为启用；不合法导入保留原配置。
- 保持原有安全规则：导出不含 API Key，导入后需重新填写密钥并测试，且不自动激活供应商。

## 验证记录（2026-09-18）

- 在本机 Python 3.11 环境运行全量测试：461 项通过（同步后的桌面源码再次测试同样通过）。
- 使用完整 Tcl/Tk 运行时重新构建 Windows 单文件 EXE，已验证主窗口标题、响应状态、正常关闭及退出码 0。
- 桌面 EXE 与通过启动检查的构建产物 SHA-256 一致。
- 本轮未进行真实第三方 API 付费调用或上游账号验证，未发布 GitHub，未删除 V4.6.1。

不修改真实用户配置或凭据，不升级 gcli2api，不自动发布 GitHub。第三方上游账户、额度与模型可用性仍需在实际环境测试；离线回归测试不能替代真实 API 验证。
