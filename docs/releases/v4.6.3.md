# V4.6.3 · 界面细节与网关可靠性修复

本版包含此前未单独发布的 V4.6.2 修复。适用于 Windows x64，下载 EXE 即可启动管理器，无需安装 Python；Claude Code 和 gcli2api 仍按各自功能需要安装和配置。

历史 Release、更新记录和附件继续保留。

## 修复

- API 切换测试与启动统一规范化服务根地址、`/v1` 和 `/v1/messages`；HTTP 200 登录页和错误 JSON 不再误判为可用。
- 修复未配置且已禁用的供应商、空供应商列表无法重新导入的问题，严格校验导入启用状态；导入不会自动激活供应商。
- API 页和配置窗口的下拉箭头不再依赖微小的字体图形；按当前 DPI 进行抗锯齿绘制。
- 常用卡片和描边按钮使用连续圆角边框，供应商选中边框稍加粗；问号按钮不再被文字内边距撑成椭圆。大面板采用九宫格边缘复用，避免整块面板高倍重绘。
- 修复本地网关上游 401/403/429 被流式 HTTP 200 空响应掩盖的问题；响应开始之前保留错误状态。
- OpenAI 流式请求申请并读取上游 usage；Gemini 原生 Anthropic 流读取 message_start/message_delta 的累计用量，不重复相加。
- 断流、无结束事件、损坏的 SSE、上游流式 error 和客户端提前退出不再记为成功。流已经开始后无法更改 HTTP 状态，此时发送安全的 SSE error 并记录失败。
- 非流式 HTML/错误 JSON 不再伪装成成功；保留正常 OpenAI 响应字段。
- 错误响应和日志不再直接回显上游响应体或网络异常原文，避免附带密钥。网关请求禁止自动跟随重定向。
- Anthropic 请求统一生成 `/v1/messages`；模型查询同时读取供应商类型、认证方式，并排除已停用供应商。
- 网关数据库 API Key 和增强网关多 Key 配置使用 Windows 当前用户 DPAPI 加密，旧格式自动迁移。

## 密钥与升级注意事项

首次使用新版本时会迁移网关本地密钥。加密数据通常只能在原 Windows 账户和机器上解密，不能把数据库当作跨电脑明文密钥备份。API 切换页原来的 Windows 凭据管理方式不变。

迁移先加密并校验，失败保留原值；多 Key 配置先加密再原子替换，读取/解密失败不会重置成空配置。旧版 EXE 不理解新增密文格式：升级后继续使用新版，不要用旧版覆盖保存同一份网关配置。现存历史备份不会被此版本自动修改或删除。

加密仅保护磁盘上的这两处网关存储，不代表进程内存、用户主动导出的备份或其他第三方配置也已加密。本次面向 Windows 桌面，非 Windows 不会降级写入明文。

DPAPI 参考：[Microsoft CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。

## 验证范围

- 原有 461 项回归测试 + 新增 43 项，共 504 项通过（Windows / Python 3.11）。
- 新增测试覆盖上游 HTTP 错误、假成功响应、UTF-8 分片、流式用量、断流与脱敏、Anthropic URL/认证、密钥迁移和失败保留。
- 控件测试覆盖浅色/深色以及 100% / 125% / 150% / 200% 缩放、悬停、禁用、选值和圆形尺寸；实际桌面对照检查浅色/深色外观。
- 发布 EXE 已使用隔离配置实际启动，检查主界面、语言下拉菜单、帮助提示和正常关闭；未替换用户的运行配置。
- API 回归使用模拟上游，不消耗真实 API 额度；尚不等同于每一家真实供应商的联网验收。
- 上游未提供 usage 时不会估算或伪造 token；本次未重写增强网关整个路由引擎，也未扩展原有 OpenAI→Anthropic 的工具调用转换。
